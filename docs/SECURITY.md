# SECURITY.md

# نظام الحماية الرسمي
## مشروع استوديو صحة الشباب

---

# الهدف

هذا الملف يحدد معايير الأمان الرسمية للمنصة.

أي تطوير جديد يجب أن يحافظ على هذه المعايير.

لا يسمح بإضافة أي ميزة تقلل مستوى الحماية.

---

# فلسفة الحماية

الأمان جزء أساسي من المشروع.

يجب حماية:

• المستخدمين.

• الإدارة.

• البيانات.

• الملفات.

• قاعدة البيانات.

• الجلسات.

• مفاتيح النظام.

---

# تسجيل الدخول

يعتمد النظام على Supabase Authentication.

يدعم:

• إنشاء حساب.

• تسجيل الدخول.

• تسجيل الخروج.

• استعادة كلمة المرور.

• تغيير كلمة المرور.

• تفعيل البريد الإلكتروني.

• استمرار الجلسة.

---

# حماية لوحة الإدارة

لا يمكن الدخول إلى لوحة الإدارة إلا بعد:

• تسجيل الدخول.

• التحقق من الجلسة.

• التحقق من الدور.

• التحقق من الصلاحيات.

أي محاولة للوصول المباشر يتم رفضها.

---

# نظام الصلاحيات

يعتمد المشروع على RBAC.

الأدوار:

• Super Admin

• Admin

• Content Manager

• Specialist

• Volunteer Manager

• Media Manager

• User

كل دور يرى فقط ما يسمح له.

---

# حماية قاعدة البيانات

تعتمد قاعدة البيانات على:

Row Level Security (RLS)

لكل جدول سياسات مستقلة.

لا يمكن قراءة أو تعديل البيانات بدون صلاحية.

---

# حماية البيانات الشخصية

يجب حماية:

• البريد الإلكتروني.

• رقم الهاتف.

• الملف الصحي.

• الرسائل.

• الاستشارات.

• الشهادات.

• الملفات الخاصة.

---

# تشفير البيانات

يجب تشفير جميع البيانات الحساسة.

لا تحفظ كلمات المرور داخل قاعدة البيانات.

يعتمد النظام على Supabase Auth.

---

# حماية الملفات

الملفات الخاصة تحفظ داخل Buckets خاصة.

لا يسمح بالوصول المباشر.

التحميل يتم فقط للمستخدم المصرح له.

---

# حماية مفاتيح النظام

لا يسمح بإظهار:

• API Keys

• Service Keys

• JWT Secret

• Tokens

• Environment Variables

يتم تخزينها داخل متغيرات البيئة فقط.

---

# حماية الجلسات

الجلسات يجب أن:

• تنتهي عند تسجيل الخروج.

• تنتهي بعد فترة خمول.

• يتم تحديثها تلقائياً.

---

# Rate Limiting

تقييد:

• تسجيل الدخول.

• إنشاء الحساب.

• إرسال الرسائل.

• النماذج.

• رفع الملفات.

• استرجاع كلمة المرور.

---

# الحماية ضد Brute Force

بعد عدة محاولات فاشلة:

• قفل مؤقت.

• تسجيل العملية.

• إشعار المدير.

---

# حماية XSS

تنظيف جميع المدخلات.

منع تنفيذ JavaScript داخل البيانات.

---

# حماية CSRF

جميع الطلبات الحساسة يجب أن تكون محمية.

---

# حماية SQL Injection

عدم تنفيذ أي استعلام مباشر.

الاعتماد على Supabase API فقط.

---

# التحقق من المدخلات

يجب التحقق من:

• النصوص.

• البريد.

• الهاتف.

• الملفات.

• الصور.

• الأحجام.

---

# رفع الملفات

التحقق من:

• الامتداد.

• الحجم.

• نوع الملف.

---

# سجل العمليات

تسجيل:

• تسجيل الدخول.

• تسجيل الخروج.

• إنشاء.

• تعديل.

• حذف.

• تغيير الصلاحيات.

• تغيير الإعدادات.

---

# تتبع الأجهزة

حفظ:

• IP

• الجهاز

• المتصفح

• وقت العملية

---

# مراقبة النشاط

كشف:

• المحاولات المشبوهة.

• تسجيل الدخول المتكرر.

• الوصول غير المصرح.

---

# النسخ الاحتياطي

نسخة احتياطية دورية تشمل:

• قاعدة البيانات.

• الملفات.

• الإعدادات.

---

# استرجاع البيانات

دعم استعادة:

• قاعدة البيانات.

• الوسائط.

• المستخدمين.

---

# قواعد الحماية

أي تطوير جديد يجب أن:

• يحافظ على جميع أنظمة الحماية.

• لا يكشف البيانات.

• لا يعطل RLS.

• لا يعطل RBAC.

• لا يعرض المفاتيح السرية.

• لا يستخدم بيانات حساسة داخل الكود.

• يحافظ على خصوصية المستخدمين.

---

# معيار الجودة

يجب أن تكون المنصة جاهزة للاستخدام الحقيقي.

أي ميزة جديدة يجب أن تمر بمراجعة أمنية قبل اعتمادها.
